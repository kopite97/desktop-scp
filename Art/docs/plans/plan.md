# 아트 PLAN 관리

적용: Art의 에셋 제작·수정·검수 계획. 탐색: [Art MAP](../../AGENTS.md), [목록](README.md), [제작 절차](../agents/workflow.md).
이 문서가 아트 PLAN 관리 규칙의 원본이다. Godot 구현·통합 작업은 [개발 PLAN 규칙](../../../docs/plans/plan.md)을 따른다.

## 작업 단위와 위치

- 실제 기록은 이 디렉터리 바로 아래 `ART-NNN-topic.md`다. README·plan.md·템플릿·evidence·references는 작업 기록이 아니다.
- 기본 작업 단위는 에셋 하나와 이번 제작 범위다. 같은 에셋의 방향·동작·보조 맵은 해당 범위에 묶을 수 있다.
- 사용자가 기존 active ART에 다른 에셋의 후속 수정을 명시적으로 묶으면 그 지시를 기록하고 포함할 수 있다. 완료된 과거 ART는 그대로 보존한다.
- 이 경우 메타데이터는 주 에셋을 유지하고 본문에 추가 AssetId별 작업/승인 리비전·검수·전달 표를 둔다. 주 에셋의 승인 숫자로 추가 에셋까지 승인됐다고 판단하지 않는다.
- ID는 ART-001부터 독립적으로 증가하며 재사용하지 않는다. 개발 PLAN-NNN과 혼용하지 않는다.
- 같은 AssetId의 리비전은 여러 ART 작업에서 이어질 수 있다. 새 작업이라고 리비전을 r001로 되돌리지 않는다.
- 현재 명세는 에셋 spec, 실행 범위·진행은 ART, 제출 당시 명세는 해당 리비전 README가 원본이다.
- 이전 제작물이 없으면 경로는 예정으로 기록하고 가상 산출물이나 빈 에셋 폴더를 만들지 않는다.

## 메타데이터와 목록

| 필드 | 값 |
| --- | --- |
| id | ART-001 형태, 파일명과 일치 |
| type | art |
| status | proposed / active / completed / on hold / rejected |
| title | 에셋과 작업 결과를 나타내는 제목 |
| asset_id | 영문자로 시작하는 영문·숫자·하이픈·밑줄 식별자 |
| revision | 현재 작업 리비전의 양의 정수. 1은 r001 |
| approved_revision | 이 작업에서 참조하는 최근 사용자 시각 승인 리비전. 없으면 0 |
| updated | YYYY-MM-DD |

- approved_revision은 revision보다 클 수 없다. 새 수정 중에는 이전 승인 번호를 유지한다.
- README는 제목과 ART 링크·작업 단위·type·status·asset_id·revision·approved_revision 표만 둔다.
- 상태와 메타데이터를 바꾸면 목록도 갱신한다. 작업 진행·피드백·승인 근거는 ART 본문에 쓴다.
- spec·제출 리비전·전달 기록은 실제 링크로 연결하고 같은 상태를 여러 문서에 복제하지 않는다.

## 승인과 active

- **사용자의 명시적 승인 없이 status를 active로 전환해서는 안 된다.**
- 새 ART는 항상 proposed로 작성한다. 제작·수정·재개 대상이 명확한 사용자 지시를 실행 근거로 기록한다.
- 구조 채택·계획 작성·기획 승인·다른 PLAN/ART 완료·검사 통과는 제작 실행 승인이 아니다.
- proposed → active, on hold → active에는 해당 작업의 명시적 승인이 필요하다.
- Art 내부 active는 최대 1개다. 0개는 정상 대기 상태다.
- 개발 PLAN도 자기 목록에서 active 최대 1개다. 개발 1개와 ART 1개가 각각 승인되어 동시에 active인 것은 허용한다.
- 한쪽 승인은 다른 쪽의 활성화·실행 승인으로 간주하지 않는다. 같은 범위의 기존 승인은 반복 요청하지 않는다.
- 다른 ART가 active라면 임의 보류하거나 두 번째를 활성화하지 않는다. 사용자 지시로 우선순위를 정리한다.
- 승인된 active 안의 피드백은 범위 내에서 계속 반영한다.
- 실제 승인 내용과 날짜·대상·범위를 ART 본문에 남긴다. 검사기는 승인 진위를 판단하지 않는다.

## 상태와 완료

- proposed: 명세를 준비하는 후보. 제작 실행 전.
- active: 승인된 현재 제작·수정·검수 대상.
- on hold: 중단 지점·사유·재개 조건을 기록한 보류.
- rejected: 취소·미채택의 근거와 보존 자료를 기록한 상태.
- completed: 필수 산출물·기술 검증·현재 리비전 사용자 시각 확인 완료.
- completed에서는 approved_revision과 revision이 같아야 한다. 숫자 일치만으로 승인 증거를 대신하지 않는다.
- 사용자 확인 대기는 본문에 표시하며 완료 조건을 줄여 completed로 바꾸지 않는다.
- completed/rejected 작업의 새 제작·수정 범위는 새 proposed ART로 작성하고 기존 기록·AssetId·리비전을 연결한다.
- 후속 ART의 리비전 진행으로 과거 completed ART의 메타데이터를 갱신하지 않는다. 과거 완료 당시 값을 보존한다.
- 전환마다 날짜·이전/새 상태·요청 또는 검증 근거를 기록한다. 후속 ART는 자동 활성화하지 않는다.

## 개발 작업과 연결

- 개발 PLAN은 Godot 상태·입력·조명·참조 연결·통합 검증을 담당한다. ART는 원본·애니메이션·보조 이미지 제작을 담당한다.
- 양쪽은 실제 문서 경로·AssetId·제출 리비전·필요한 경우 요청 ID로 연결한다. 번호가 같을 필요는 없다.
- 동시 작업 시 Art 작업용 source는 제작 작업이, Godot 제품 파일은 개발 작업이 담당한다.
- 개발 작업은 기록된 제출 export를 사용한다. 편집 중 source를 자동 수신하거나 최신 파일을 무조건 교체하지 않는다.
- 공통 규격 변경은 관련 작업에 영향을 기록하고 기존 요청 범위를 확인한다.
- 아트 완료·사용자 시각 확인·Godot 수령·실제 적용은 구분한다. 적용 자체가 아트 PLAN의 필수 조건이면 그 증거까지 연결한다.
- 조명 방식·기본색/보조 맵 범위·엔진 시험 담당·샘플 증거는 [조명 지침](../agents/lighting.md)에 따라 명시한다. 조명용 제작은 샘플 검증 후 전체 프레임으로 확장한다.
- 조명용 리소스가 범위인 ART는 엔진 샘플 검증이 완료 조건이다. 다른 제품 기능의 완료를 선행 조건으로 확대하지 않는다.

## 작성·저장·검사

1. [_template.md](_template.md)를 이 디렉터리의 새 ART 파일로 복사한다.
2. 목표·포함/제외·요청 근거·선행 조건·규격·산출물 위치·완료 기준을 정한다.
3. 원본·제출본·리뷰와 PLAN별 참고 이미지 위치·명명은 [아트 구조](../agents/project-structure.md)와 [리비전](../agents/revisions.md)을 따른다. 참고 폴더 README를 ART에 연결하고 채택 기준을 적는다.
4. 실행 로그·결과는 `Art/docs/plans/evidence/ART-NNN/run-NNN/`에 저장한다. 원본과 리뷰는 복제하지 않고 연결한다.
5. 실제 결과·미검증·현재 상황·다음 행동을 ART에 갱신한다.

프로젝트 루트에서 `node scripts/validate-agent-docs.mjs`, Art 루트에서는 `node ../scripts/validate-agent-docs.mjs`를 실행한다.
검사 범위는 필수 문서·길이·메타데이터·목록·스코프별 active 수·로컬 파일 링크다.
픽셀 품질·승인 사실·Godot 적용은 [아트 검증](../agents/verification.md)에 따라 별도로 확인한다.
이 관리 문서는 150줄 이내로 유지한다.
