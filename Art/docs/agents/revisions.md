# 리비전과 피드백

적용: 제출·수정·승인본 보존. 탐색: [구조](project-structure.md), [리비전 양식](../../templates/revision.md).

## 번호와 원본

- 에셋 최초 제출은 r001, 이후 제출본 수정은 r002처럼 증가시킨다. 에셋별로 독립 번호를 쓴다.
- 아직 제출하지 않은 작업용 초안은 매 저장마다 번호를 올리지 않는다.
- 제출 시점 source·export·README·review를 같은 리비전으로 묶어 보존한다.
- 제출한 그림을 바꿀 때 기존 리비전을 덮어쓰지 않는다. 채택되지 않은 번호도 재사용하지 않는다.
- 문서 오타·링크·진행 기록만 바꾸는 경우 그림 리비전을 올리지 않는다.
- 최신 작업 리비전·최신 제출·사용자 승인·실제 Godot 적용 리비전을 각각 기록한다.

## 피드백

| 항목 | 기록 |
| --- | --- |
| 식별 | F-001 등의 ID·날짜 |
| 대상 | 리비전·방향·동작·프레임·레이어·부위 |
| 요청 | 관찰한 문제와 원하는 변경·참조 |
| 처리 | 미처리·반영·보류·미채택과 근거 |
| 결과 | 반영 리비전·재검수 결과·남은 문제 |

기존 승인 범위의 피드백은 계속 처리한다. 새 표현·동작 범위를 추가하면 기존 ART와 요청 범위를 대조한다.
최종 사용자 시각 확인은 대상 리비전·날짜·실제 의견에 연결한다. 파일 수정 시각으로 승인을 추측하지 않는다.

## ART와 리비전

- AssetId와 리비전 이력은 여러 ART에서 이어서 참조할 수 있다.
- active ART 안의 수정은 같은 ART에서 추적한다.
- completed ART의 새로운 제작·수정 작업은 [Art PLAN 규칙](../plans/plan.md)에 따라 새 proposed ART로 작성한다.
- 참고 Art의 completed → active 재개 예외는 이 프로젝트에 복사하지 않는다.
- 이전 승인·완료·전달 기록을 유지하고 새 작업이 과거 완료를 취소한 것처럼 쓰지 않는다.
