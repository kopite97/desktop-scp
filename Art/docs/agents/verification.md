# 아트 검증

적용: 제출과 완료 판정. 탐색: [프로젝트 검증 규칙](../../../docs/agents/verification.md).

## 확인 항목

| 구분 | 확인할 내용 |
| --- | --- |
| 파일 | 실제 파일·리비전·크기·알파·모드·팔레트·출력 레이어 |
| 시트 | 셀 크기·순서·여백·태그·프레임 범위·시간 |
| 형태 | 외곽선·실루엣·반투명·원본 크기 가독성·밝고 어두운 배경 |
| 애니메이션 | 실제 시간 재생·반복 경계·정렬·의도하지 않은 부피 변화 |
| 원본 대응 | 편집 source와 제출 source/export의 같은 리비전 여부 |
| 사용자 확인 | 대상 리비전·확인 날짜·사용자 의견·남은 수정 |
| Godot 적용 | 실제 파일/참조·재생·배율·입력 영역·사용자 화면 확인 |
| 조명·재질 | [조명 검증 표](lighting.md)의 좌/우/위 빛·낮/밤·반전/변형·알파·다중 창·성능 |

## 판정과 증거

- 기대 결과·실제 실행한 방법·환경·결과·증거·미확인 항목을 남긴다.
- 정지 접촉표만 본 상태를 실제 애니메이션 재생 통과로 기록하지 않는다.
- 원본/출력 기술 검사와 사용자 시각 확인을 구분한다. 미확인 상태는 그대로 남긴다.
- ART는 [완료 규칙](../plans/plan.md)에 따라 자기 범위의 산출물·필수 검증·현재 리비전의 사용자 시각 확인을 충족한 경우 완료한다.
- 사용자 확인을 기다린다는 이유로 승인된 독립적인 기술 작업을 중단하지 않는다.
- 제품 적용이 범위 밖이면 제작 완료와 제품 적용 대기를 별도로 표시한다.
- 조명용 리소스가 범위이면 엔진 샘플 검증을 필수 기준으로 둔다. 형태·동작 시각 확인, 조명 검증, 전체 최종 확인을 구분한다.
- 수정 후에는 바뀐 항목과 영향받는 결과를 검증한다. 관련 없는 검사를 반복하지 않는다.
- 하네스 문서 검사 통과는 아트 품질·Live 연결·Godot 적용 성공을 의미하지 않는다.

## 문서 검사

프로젝트 루트에서 `node scripts/validate-agent-docs.mjs`를 실행한다.
검사기 자체를 변경하면 `node --test scripts/validate-agent-docs.test.mjs`도 실행한다.
Art MAP·지침 길이·로컬 링크·필수 문서·ART 메타데이터/목록 일치·개발과 아트 각각의 active 제한을 검사한다.
픽셀 품질·승인 사실·출력 이미지 규격을 이 문서 검사기가 자동 검증한다고 주장하지 않는다.
