# 도트 디자인과 규격

적용: 외형·색·규격·샘플. 탐색: [기획 원본](../../../SCP_site-desktop.md), [명세 양식](../../templates/asset-spec.md).

## 기획에서 확정된 기준

- 2D 픽셀 아트, 2등신 SD 데포르메, SCP의 기괴한 특징과 귀여움의 공존.
- 모든 도트 스프라이트 외곽에 1px 다크 아웃라인을 적용한다. 표시 확대 배율과 원본 픽셀 단위를 구분한다.
- SCP-999는 반투명 주황 슬라임, SCP-173은 콘크리트 조각상과 붉은색/초록색 얼굴 무늬, SCP-049는 검은 망토와 흰 새 부리 가면이다.
- 동작·효과의 실제 제작 범위는 승인된 PLAN에서 정한다. 기획에 있다는 이유로 모든 아트를 한 번에 제작하지 않는다.

## 캐릭터 기본 해상도

- 2026-11-23 사용자의 해상도 결정 요청에 따라 SCP-999·173·049의 기본 프레임 캔버스를 **64×64 원본 픽셀**로 정한다.
- 이 값은 애니메이션 한 프레임의 셀 크기다. 스프라이트 시트 전체 크기나 몸체의 너비·높이가 아니다.
- 캔버스에는 몸체·외곽선·투명 여백을 포함한다. 같은 에셋의 동작·방향 프레임은 동일한 셀을 유지한다.
- 정지 자세로 셀을 꽉 채우지 않는다. SCP-999의 눌림·출렁임 등 가장 큰 변형까지 들어갈 여백을 에셋 명세에서 확보한다.
- 1px 다크 아웃라인은 원본 기준이다. 최초 화면 검수는 nearest 방식 2배 표시, 즉 셀 기준 128×128 화면 픽셀을 기준으로 한다.
- 2배는 초기 표시·검수 기준이며 최종 사용자 크기 옵션이나 모든 DPI 환경의 시각 검수 완료를 뜻하지 않는다.
- 작업 원본과 PNG 출력은 1배 해상도를 유지한다. 표시 크기 조정은 제품 쪽 정수 배율로 처리한다.
- 32×32는 작은 아이콘·단순 오브젝트의 후보, 128×128은 별도의 고해상도 표현이 필요한 에셋의 예외 후보로 둔다.
- 캐릭터 기본 규격을 바꾸거나 예외 크기를 쓰면 해당 에셋의 필요·시각 비교·동작/입력 영역 영향을 기록한다.
- 근거: 64×64는 2등신 실루엣과 049 가면·173 얼굴 무늬·999 변형을 표현할 여유와 프레임별 수정 부담의 균형을 고려한 제작 판단이다.

캔버스 크기와 그림 내용 리사이즈는 별개다. [Aseprite 공식 크기 문서](https://www.aseprite.org/docs/sprite-size/)를 참고한다.
현재 제품 코드·임시 표현은 변경하지 않았다. 실제 정지 샘플·짧은 애니메이션의 시각 검수는 제작 단계에서 수행한다.

## 아직 정해야 하는 값

캐릭터별 그림 영역·여백·최종 표시 옵션·팔레트 파일·색 수·시점·방향 수·광원·그림자·알파 수치는 각 명세에서 정한다.
조명 방식과 제작/엔진 책임은 [조명과 재질 지침](lighting.md)을 따른다. 구체 수치가 미정이라는 이유로 조명 준비 절차까지 생략하지 않는다.
PLAN-003의 128×128 창은 초기 2배 표시 셀과 크기가 같지만 임시 다각형을 정식 실루엣·입력 윤곽으로 사용한다는 뜻은 아니다.
참고 프로젝트의 PPU 32·지하 연구실 광원·보조형 점눈 규칙은 이 프로젝트의 기준이 아니다.

## 에셋별 명세

- 캔버스 크기, 그림이 차지하는 영역과 투명 여백, 바닥 접점·피벗·원점·단위를 기록한다.
- 외곽선·명암 단계·팔레트·반투명 부위와 출력 색상 모드/프로파일을 기록한다.
- 필요한 방향·동작과 좌우 반전 허용 여부, 동작별 그림 영역 변화와 여백을 적는다.
- 채택한 참조·사용자 피드백의 실제 위치를 연결하고 제안값과 확정값을 구분한다.
- 기준 샘플은 정지 모습과 필요한 짧은 동작을 실제 표시 크기에서 먼저 확인한다.
- 동적 조명용 기본색과 고정 명암 시안을 구분하고 Body·Highlights 모두의 방향성 명암을 점검한다. 조명 시험 전 보조 맵을 전체 동작으로 대량 확장하지 않는다.

## 품질 확인

- 실제 크기와 정수배 확대로 확인한다. 실루엣·색 덩어리·선 굵기·고립 픽셀·의도하지 않은 중간색을 살핀다.
- 밝은 배경·어두운 배경·무늬가 있는 테스트 배경에서 외곽선과 반투명 몸체가 읽히는지 확인한다.
- 사용자 문서 화면 대신 테스트 배경을 사용하고 실제 데스크톱 관찰과 모의 배경 결과를 구분한다.
- 형태와 표정·동작으로 역할을 전달한다. 색 차이만으로 상태를 구분하지 않는다.
- 확대된 한 장의 보기 좋은 결과만으로 애니메이션·실제 표시 품질을 통과 처리하지 않는다.
