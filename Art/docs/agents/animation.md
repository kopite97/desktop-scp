# 애니메이션과 정렬

적용: 방향·상태·프레임·시간. 탐색: [디자인](design.md), [전달](handoff.md).

## 동작 계약

- 승인된 PLAN의 실제 상태와 필요한 표현을 연결한다. 예시 idle·move·pet 등을 구현된 상태로 기록하지 않는다.
- 태그명, 방향, 프레임 범위, 각 프레임 시간(ms), 반복/일회/왕복, 종료 후 자세를 명세에 적는다.
- 전체 공통 FPS나 프레임 수를 임의로 정하지 않는다. 불균일 시간을 평균 FPS 하나로 대체하지 않는다.
- Aseprite 도구의 프레임/태그 인덱스는 1부터 시작한다. Godot 연결 시 실제 데이터의 인덱스 규약을 확인해 명시적으로 변환한다.
- 정적 변형을 프레임으로 관리하면 애니메이션이 아닌 변형 선택임을 표시한다.

## 제품 상태가 추가로 필요한 동작

- spawn·collect·expire 등 태그마다 실제 시작 사건, 시간 소유자, 정상 종료, 취소/중단, 봉쇄/복귀, 앱 종료 처리를 명세한다. 미구현 상태는 필요한 개발 항목으로 표시한다.
- 논리 삭제 뒤 재생하는 소멸 동작은 대상·입력·예약·생존 수/회수 판정을 즉시 끝내고 표시 전용 수명을 따로 두도록 제품 담당에게 전달한다. 아트 재생 때문에 게임 객체의 삭제나 보상을 늦추지 않는다.
- 표시 전용 객체가 필요로 하는 이미지 스냅샷·캐시 참조·최대 수명·마지막 투명 프레임·중복 사건 처리와 자원 해제를 handoff에 적는다.
- 게임 성공과 동시에 시작하는 등장/변이는 같은 사건을 기준으로 한다. 그림의 길이나 독립 타이머가 게임 성공을 발생시키게 만들지 않는다.
- 정상/가속된 게임 진행과 반복 클립 속도를 구분한다. 중단 가능한 반복은 종료 사건까지 재생하며, 현재 값에만 맞춘 고정 길이로 대체하지 않는다.
- 알파/소멸은 원본 프레임과 엔진 중 담당자를 정한다. 런타임 아이콘 몸체와 추가 부착물의 fade가 다르면 각각의 소유자를 명시한다.
- [아이콘 좀비 연결 계약](../../../docs/game-design/icon-zombie-presentation.md)은 ART-006/007의 구체 적용 사례다. 별도 개발 PLAN에서 구현·검증할 때까지 제작 완료와 제품 동작 완료를 구분한다.

## 정렬과 형태

- 세트 내 캔버스·바닥 접점·피벗 기준을 공유한다.
- 눌림·출렁임·점프 같은 의도적 변형과 프레임 실수로 생긴 부피 변화·위치 흔들림을 구분한다.
- 비대칭 외형·광원을 확인한 후 좌우 반전 재사용 여부를 정한다.
- 몸체·그림자·효과를 분리하면 공통 좌표와 재생·합성 관계를 적는다.
- 동작 중 가장 크게 뻗는 프레임까지 여백·창 경계에 잘리지 않는지 확인한다.
- 조명용 맵의 프레임·태그·시간·피벗·변형 대응과 좌우 반전은 [조명 지침](lighting.md)을 따른다. 늘어진 몸체에 정지 노멀맵을 그대로 재사용해도 되는지 실제 재생으로 확인한다.

## 재생 검수

- 정지 프레임 접촉표와 실제 시간 재생을 모두 본다.
- 반복의 마지막→첫 프레임, 상태 전환, 정지·복원 시 모습을 확인한다.
- 보행은 몸체가 실제 이동하는 상태에서 양방향을 확인한다. 접지한 발은 몸체 기준 진행 방향 반대로 이동하고, 들린 발은 앞으로 돌아오는지 확인한다. 발끝 방향·좌우 위상·지면 미끄러짐을 구분하며, 제품 재생 순서를 보정하면 원본 리비전과 런타임 매핑을 handoff에 따로 기록한다.
- Aseprite에서 재생 확인한 범위와 Godot에서 이동 속도·입력 상태와 연결해 확인한 범위를 구분한다.
- 스프라이트 변경 후 입력 윤곽이 몸체를 따라가는지는 제품 검증이다. 기존 임시 다각형에 맞춰 그림을 왜곡하지 않는다.
