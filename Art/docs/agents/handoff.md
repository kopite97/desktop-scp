# 출력과 Godot 전달

적용: 제출 PNG·시트·프레임 정보·제품 적용 대응. 탐색: [전달 양식](../../templates/handoff.md).

## 명세와 출력

- .aseprite 작업 원본과 제출 보존본은 Art에 둔다. PNG 시트가 기본 전달 후보이며 실제 형식은 요청 명세로 정한다.
- 프레임 크기·행/열·순서·여백·간격·태그·프레임 시간(ms)·반복 방식·피벗·바닥 접점을 명시한다.
- 원본 좌상단을 (0,0), X 오른쪽·Y 아래쪽의 픽셀 좌표로 기록하고 다른 단위라면 변환을 명시한다.
- 트리밍·회전·중복 병합은 프레임 위치를 바꿀 수 있다. 기본적으로 고정 셀을 보존하고 실제 연동이 지원하는 경우에만 별도 설정을 기록한다.
- 반투명 SCP-999의 알파를 유지한다. GIF 미리보기를 반투명 PNG 원본 대신 제품에 사용하지 않는다.
- PNG에 포함되지 않는 프레임 시간·태그·피벗은 명세나 JSON에 남긴다.
- Aseprite JSON이 자동으로 Godot 애니메이션에 연결된다고 가정하지 않는다. 현재 전용 importer는 구현하지 않았다.
- 조명 방식·기본색/보조 맵 역할·맵별 채널/색 공간·반전 계약·샘플 시험 결과를 [조명 지침](lighting.md)에 따라 함께 전달한다. 미검증 시안을 조명 대응 완료본으로 넘기지 않는다.

## 요청·수령·적용

1. 개발 PLAN·제작 ART·에셋 명세를 실제 문서 경로로 연결한다. 여러 요청이 필요하면 PLAN-NNN-SPR-001 형태로 구분한다.
2. Art의 제출 리비전 README에서 필요한 export 파일과 기술 검증 결과를 확인한다.
3. 같은 에셋의 spec에 연결한 handoff 기록에 수령·적용·사용자 확인을 따로 기록한다.
4. 제품 적용 승인이 있는 범위에서 필요한 런타임 파일만 GodotProject에 복사하고 참조를 연결한다.
5. 최종 적용 경로·적용 리비전·프레임 매핑·검증 결과를 기록한다. 최신 제출을 자동 적용본으로 간주하지 않는다.

예정 최종 경로: `GodotProject/Assets/Sprites/<category>/<AssetId>/`.
이는 규격이며 지금 에셋이나 폴더가 생성된 것은 아니다.
런타임이 Art 작업용 source나 review를 직접 참조하지 않게 한다.
같은 저장소 안이므로 별도 수령 파일 사본을 무조건 만들지 않고 제출 export 경로를 기록한다.
전달 시 AssetId·리비전을 고정한다. ART 완료와 개발 PLAN의 적용 완료·실행 승인은 서로 대신하지 않는다.

## Godot 연결 시 확인

- 원본 픽셀을 흐리지 않는 nearest 필터와 의도한 정수 표시 배율을 실제 노드·프로젝트 설정에서 확인한다.
- Unity의 PPU·Sprite Mode·.meta 규칙을 적용하지 않는다. Godot에서 실제 사용할 텍스처·프레임·기준점을 확인한다.
- 방향·태그·프레임 시간·한 번/반복 재생을 게임 상태와 연결하고 실제 재생을 확인한다.
- [추가 동작 연결 지침](animation.md)에 따라 태그별 사건·시간·취소·삭제 후 표시 수명·캐시 해제와 미구현 개발 항목을 전달한다. 시트 교체만으로 collect/expire 등이 구현된다고 가정하지 않는다.
- 다중 부착물/효과는 출력 파일별 합성 순서·좌표·실제 표시 크기와 필요한 창 영역을 명시한다. 제작 셀의 크기와 현재 제품 창의 크기를 대조하고 입력 여부를 따로 기록한다.
- 프레임의 투명 여백·몸체·그림자·효과와 클릭 영역의 관계를 제품 담당 PLAN에 전달한다.
- 정식 아트를 적용해도 빈 공간·개체 사이 클릭 투과, 이동·숨김·복원·종료는 유지되어야 한다.
- 그림 원본 품질·Godot 표시·Windows 입력 판정은 서로 다른 검증이다.

프레임 크기·외곽선·배율 변경은 화면 크기와 입력 영역에 영향을 준다.
제품 구현이 지원하지 않는 출력은 명세 차이를 기록하고 승인된 범위에서 연결 방식을 정한다.
