# 조명과 재질 제작·전달 지침

적용: 캐릭터·VFX의 기본색, 고정 명암, 노멀/반사 맵, 조명 시험과 Godot 전달.
탐색: [디자인](design.md), [애니메이션](animation.md), [전달](handoff.md), [검증](verification.md).

## 먼저 정할 표현 방식

- 새 ART와 에셋 spec에 조명 방식을 기록한다. 비워 두거나 “나중에 엔진에서 처리”만 적지 않는다.
- 선택은 동적 조명 대응 / 조명 영향 없는 표현 / 기존 고정 명암 시안으로 구분한다.
- 캐릭터는 동적 조명 대응을 기본 검토 대상으로 둔다. UI·작은 반응 기호는 가독성 때문에 조명 영향을 받지 않는 방식을 선택할 수 있으며 사유를 기록한다.
- 기존 고정 명암 시안은 형태·동작 비교용으로 보존한다. 조명 준비 완료로 분류하지 않는다.
- 기술 방식을 채택하는 것과 해당 ART·개발 PLAN 실행 승인은 별개다. [계획 승인 규칙](../plans/plan.md)을 유지한다.

## Art와 Godot의 책임

| 대상 | Art | Godot 개발 |
| --- | --- | --- |
| 기본색·표정·윤곽 | 형태·재질색·알파·픽셀 구조 | 텍스처/재질 연결·정수 배율 |
| 노멀맵 | 표면 방향 데이터·변형별 대응 | 좌표 규약·조명 반응·반전/회전 처리 |
| 반사 맵 | 반사가 나타날 부위/값의 명세 | 선택한 셰이더의 채널 의미·광택/반사 파라미터 |
| 발광 마스크 | 필요한 경우에만 발광 부위 분리 | 발광 합성·빛 방출 여부·세기 |
| 그림자 | 필요할 때 접지 그림자 이미지 | 배치·크기·농도·빛 방향·생성/정리 |
| 시간대 | 시간별 이미지 세트를 기본 요구하지 않음 | 공유 시간 상태·주광원/주변 밝기·전환 |
| 검증 | 원본/출력 대응·픽셀·애니메이션 검수 | 실제 렌더러·창·입력·성능 검증 |

## 고정 명암과 기본색

- 동적 조명용 기본색에 특정 방향의 햇빛·강한 반짝임·투사 그림자를 굽지 않는다.
- 색 덩어리·윤곽·표정을 읽기 위한 최소한의 비방향성 음영은 허용한다. 유지 이유와 조명 비교 결과를 기록한다.
- Body에 들어간 명암과 Highlights 레이어를 함께 점검한다. Highlights만 숨겨도 기본색이 중립화되었다고 판단하지 않는다.
- 기본색·표정/윤곽·재질 반사·보조 데이터는 편집 가능하게 분리한다. 고정 반사와 동적 반사를 중복 적용하지 않는다.
- 노멀맵은 그림의 밝기를 그대로 변환한 명암 지도가 아니다. 몸체·팔·늘어진 꼬리의 표면 방향을 표현한다.
- 반투명과 반사는 다른 속성이다. 알파를 낮추거나 흰 점을 추가한 것만으로 젤리 재질이 검증되었다고 하지 않는다.
- 발광 마스크는 노멀/반사 맵의 대체물이 아니다. 실제로 빛을 내는 연출이 요구된 에셋에만 작성한다.

## 조명 제외 범위와 외곽선

- 에셋별로 몸체·표정·외곽선·VFX의 조명 적용/제외 범위를 명세한다. Aseprite 레이어 분리만으로 Godot 조명이 제외되지는 않는다.
- 작은 하트/음표는 전체 PNG를 CanvasItemMaterial LightMode.Unshaded로 표시한다. 기본색 PNG는 straight RGBA/Mix, 투명 Viewport 결과는 해당 premultiplied 계약으로 합성한다.
- 본체 외곽선만 제외할 때는 lit 기본색과 unlit 외곽선을 별도 출력·노드로 분리한다. 외곽선 픽셀을 lit 출력에도 남겨 중복 합성하지 않는다.
- 분리 시 원래 합성 RGBA·1px 굵기·커버리지를 보존한다. 부분 알파가 겹치는 경우 단순 제거로 원본을 재구성할 수 있는지 검사한다.
- 본체/외곽선의 셀·프레임·ms·피벗·배율·FlipH·가시성은 한 재생 상태에서 동시에 갱신한다. 표정까지 unlit로 바꾸는 것은 별도 범위다.
- 조명 제외 노드에는 부모의 주야간 modulate 색을 상속시키지 않는다. 중립 공통 부모 아래 lit 본체와 unlit 외곽선/효과를 두고 필요한 색 변조는 본체 self_modulate에 한정한다.
- Unshaded는 강제 불투명/발광 설정이 아니다. 원본 알파·수명·숨김을 유지하고 외곽선만 남거나 이중 fade가 생기지 않게 한다. 불필요한 emission 맵은 만들지 않는다.
- Light2D 방향/세기/색, CanvasModulate, 부모 색 변조를 각각 구분해 시험한다. 조명 제외 픽셀의 출력 RGB/alpha가 유지되고 lit 몸체는 계속 반응해야 한다.
- 비교는 동일 배경·1배/2배·낮/밤·좌우 반전·실제 ms 재생으로 수행한다. 반투명 경계·이음새·두 겹 윤곽·입력 영역·추가 렌더 비용을 확인한다.
- 승인된 제출본은 보존하고 새 리비전에서 변경한다. 파일 검증·엔진 적용·최종 시각 확인을 각각 기록한다.

## 소수 프레임으로 먼저 검증

1. 목적·조명 방식·제작 ART·엔진 시험 담당 PLAN을 연결한다. 미지정 담당과 미승인 실행은 그대로 표시한다.
2. 대표 정지 1프레임과 변형이 큰 이동 2~3프레임으로 기본색·노멀·필요한 반사 맵을 준비한다.
3. 기존 고정 명암 시안, 중립 기본색만 사용한 결과, 조명+보조 맵 결과를 동일 조건에서 비교한다.
4. Godot의 실제 대상 렌더러·투명 창에서 아래 검증 표를 실행하고 환경·설정·증거를 남긴다.
5. 품질·성능·반전 계약이 확인된 뒤 전체 프레임으로 확장한다. 샘플이 맞지 않으면 맵/셰이더/범위를 먼저 조정한다.

- 엔진 시험이 미승인이거나 미완료이면 보조 맵 대량 제작을 보류한다. 승인된 독립적인 형태·동작 작업은 계속할 수 있다.
- 변형이 있는 프레임에 정지 노멀맵을 무조건 복사하지 않는다. 재사용은 실제 표면 변화와 재생 결과로 판단한다.
- 조명용 리소스 완성을 범위에 넣었다면 샘플 시험은 그 완료 조건이다. 전체 게임 기능 통합 완료를 요구하는 것은 아니다.

## 출력 계약

- 모든 맵은 같은 AssetId·리비전의 기본색과 대응한다. 셀 크기·시트 배열·프레임 순서·태그·시간·피벗·트리밍 정책을 일치시킨다.
- 예정 파일명은 <AssetId>_color.png, <AssetId>_normal.png, <AssetId>_specular.png로 명세한다.
- 선택 파일은 <AssetId>_emission.png·<AssetId>_shadow.png 등 용도를 드러낸다. 기존 <AssetId>.png를 쓸 경우 역할과 호환 관계를 명시한다.
- 독립 접지 그림자는 본체 시트와 다른 규격을 쓸 수 있다. 크기·피벗·합성 순서·재생/변형 연결을 별도로 명세한다.
- 기본색은 표시용 색 데이터, 노멀·마스크는 수치 데이터다. 맵별 채널 의미·색 공간·임포트 설정·알파 사용/무시 여부를 기록한다.
- 노멀맵의 X/Y/Z 방향과 대상 엔진 버전을 명시한다. 기본색 팔레트로 노멀 색상을 양자화하거나 팔레트 교체하지 않는다.
- 반사 맵은 사용하는 재질의 채널 의미를 따른다. “밝을수록 반사가 강함” 같은 설명만으로 엔진 계약을 대신하지 않는다.
- 좌우 반전 시 기본색의 위치 반전과 노멀 벡터 처리를 함께 시험한다. 기본 기능이 처리하는지 확인하지 않고 채널을 이중 반전하지 않는다.
- 1px 윤곽 규칙은 표시되는 색상 스프라이트에 적용한다. 데이터 맵에 검정 외곽선을 임의로 그려 넣지 않는다.
- 투명 경계의 데이터 패딩·필터·반복 설정을 확인한다. 팔·꼬리 경계에 검은 테두리/빛 번짐이 생기지 않아야 한다.
- 제출본은 기존 revisions/rNNN/source·export·review에 보존한다. 승인된 과거 제출물을 새 조명용 파일로 덮어쓰지 않는다.

## Godot 시험·성능 기준

- 초기 비교안은 주광원 하나+주변 밝기+간단한 접지 그림자다. 실제 노드/셰이더 선택은 담당 개발 PLAN에 기록한다.
- 기본 기능으로 품질이 충분한지 먼저 비교한다. 커스텀 셰이더·추가 광원·동적 투사 그림자는 필요한 차이와 비용을 확인한 뒤 선택한다.
- 픽셀의 정수 배율·nearest와 알파 경계를 유지한다. 부드러운 조명과 단계화한 조명을 비교해 도트가 흐려지거나 반짝이지 않는 쪽을 채택한다.
- 여러 네이티브 창/Viewport는 같은 조명 상태를 사용한다. 창마다 시간·빛 방향을 따로 계산해 이음새가 달라지지 않게 한다.
- 밤에도 몸체·표정·1px 윤곽을 식별할 최소 가독성을 정한다. 모든 에셋을 동일하게 어둡게 만드는 것으로 끝내지 않는다.
- 이 프로젝트가 그리는 오버레이의 색/그림자와 뒤쪽 실제 데스크톱의 조명은 구분한다. 실제 앱 배경까지 엔진 빛을 받는 것으로 간주하지 않는다.
- 그림자·빛 효과·투명 여백은 클릭 영역에 자동 포함하지 않는다. 창 경계 잘림·숨김/복원·입력 투과를 함께 확인한다.
- 성능 비교는 같은 해상도·렌더러·개체/창 수·관찰 시간에서 조명 전/후 프레임 시간·CPU/GPU·메모리를 기록한다.
- 수집 불가한 지표는 미측정으로 쓴다. 수치 목표·허용 비용·단순화 순서는 시험 PLAN에서 정하고 미측정을 통과로 처리하지 않는다.

## 시간대 연출 계약

- 로컬 시간 연동을 채택할 경우 시간→빛 방향·색·주변 밝기 변환은 Godot에서 수행한다.
- 로컬 시각에 따른 연출과 위치/날짜를 사용하는 실제 태양 위치 계산을 구분한다. 위치 수집·해 아이콘 표시를 자동으로 추가하지 않는다.
- 수동 낮/밤·고정 광원 모드로 같은 결과를 재현할 수 있게 시험한다.
- 시간 변경·절전 복귀·날짜 경계·여러 창의 동기화와 전환 방법을 개발 명세에 기록한다.
- 정확한 낮/밤 시간표·최저 밝기·전환 속도·사용자 옵션은 제품 PLAN에서 확정한다. 이 지침은 해당 수치나 기능 실행 승인이 아니다.

## 검증과 완료 구분

| 조건 | 확인할 결과 |
| --- | --- |
| 좌/우/위 조명 | 반사와 명암이 광원을 따르며 고정 반짝임이 반대쪽에 남지 않음 |
| 낮/밤·세 배경 | 색·표정·반투명·윤곽 가독성 유지 |
| 변형·좌우 반전 | 프레임/맵 정렬, 법선 방향, 팔·꼬리의 반사 떨림 없음 |
| 정지·이동 재생 | 1배/2배에서 불필요한 명암 깜빡임·픽셀 번짐 없음 |
| 창·입력 | 여러 창 조명 일치, 경계 잘림·효과 입력 차단 없음 |
| 비용 | 같은 조건의 조명 전/후 측정과 채택 근거 |

- 형태·동작 확인 / 조명용 파일 준비 / 엔진 조명 샘플 검증 / 전체 프레임 검증 / 최종 사용자 확인 / 제품 적용을 따로 기록한다.
- 형태가 괜찮다는 의견을 조명·전체 최종 승인으로 확대하지 않는다.
- 조명 영향 없는 에셋도 이유와 낮/밤 합성 가독성을 확인한다. 불필요한 노멀/반사 맵을 의무 생성하지 않는다.
- 문서 검사기는 링크·길이·메타데이터를 확인한다. 이 표의 이미지 의미·실시간 품질·성능을 자동 판정하지 않는다.

## 근거와 적용 한계

- [CanvasTexture 공식 문서](https://docs.godotengine.org/en/stable/classes/class_canvastexture.html): 2D 기본색·노멀·스페큘러 지원 및 채널/좌표 의미. 해당 엔진 버전의 설정을 실제 시험한다.
- [2D 조명 공식 문서](https://docs.godotengine.org/en/stable/tutorials/2d/2d_lights_and_shadows.html): 광원·주변색·그림자 구성.
- [CanvasItem 셰이더 공식 문서](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html): 조명 제외 표현과 블렌딩 방식.
- 문서 확인일: 2026-11-23. API 지원은 현재 프로젝트에서 구현·성능 검증되었다는 증거가 아니다.
