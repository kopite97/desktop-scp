# 아트 작업 절차

적용: 아트 작업 시작·재개·마감. 탐색: [Art MAP](../../AGENTS.md).

## 시작

1. 사용자 요청, 실제 파일과 진행 중 변경, 기존 명세·피드백을 읽는다.
2. 프로젝트 루트에서 `node scripts/validate-agent-docs.mjs`를 실행한다.
3. [아트 PLAN 목록](../plans/README.md)과 [승인 규칙](../plans/plan.md)을 확인한다.
4. 제작 작업이면 승인된 active ART의 에셋·리비전·제작 범위·전달 대상을 확인한다.
5. 대상에 맞는 디자인·애니메이션·Aseprite 지침을 읽고 편집할 파일을 명시한다.
6. [조명과 재질](lighting.md)에 따라 조명 방식·고정 명암·보조 맵 필요 여부·엔진 시험 담당을 명세한다. 동적 조명용 맵은 대표 샘플 검증 후 전체 프레임으로 확장한다.

아트 하네스 관리·명세 조사 요청은 PLAN을 임의 활성화할 근거가 아니다.
정식 제작·교체는 해당 실행 범위를 확인한다. 이미 승인된 수정 범위는 반복 승인받지 않는다.
제작 주체와 역할은 실제 사용자 요청을 따른다. 참고 프로젝트의 사용자 직접 제작 전용 규칙을 자동 이식하지 않는다.
에이전트에게 제작이 위임되면 해당 범위에서 Aseprite로 작업하고 변경·검수 근거를 남긴다.

## 기준과 책임

- 제품 외형·동작의 기준은 [기획 원본](../../../SCP_site-desktop.md)과 해당 ART·연결된 개발 PLAN이다.
- 공통 아트 지침과 제작 진행 ART는 Art 내부, 기술 선택은 프로젝트 TECH에 둔다.
- 게임 코드·씬·상호작용 규칙 변경은 별도 제품 구현 범위다. 그림 제공만으로 기능 구현을 승인받았다고 해석하지 않는다.
- 에셋 목록은 파일·ART 탐색용이며 ART status의 별도 원본이 아니다.
- 실제 픽셀 수정 전 작업 중인 파일·저장 상태를 확인한다. 다른 프로젝트의 원본과 승인본을 덮어쓰지 않는다.

## 마감

1. 변경한 원본·제출본·출력·대상 리비전을 연결한다.
2. [검수](verification.md) 결과와 미실행 항목을 기록한다.
3. 기술 검사와 사용자 시각 확인, 전달과 실제 적용을 구분한다.
4. ART 및 필요한 에셋 목록·전달 기록을 갱신한다. 개발 PLAN에는 전달·적용에 필요한 연결을 남긴다.
5. 문서 검사 후 완료 범위·남은 검수·다음 행동을 보고한다.

외형·색감·움직임의 최종 사용자 확인은 해당 리비전에 연결한다.
기술 검사 통과를 사용자 승인으로 기록하지 않는다.
