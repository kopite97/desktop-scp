# TECH-018 모니터 전이 상태와 중립 생성 위치 정책

- 근거: 2026-11-26 사용자 [PLAN-018](../plans/PLAN-018-monitor-portals-and-local-spawning.md) 실행 승인.
- 제품 계약: [행동](../game-design/scp-behavior.md), [아이콘 생성](../game-design/desktop-icon-clones.md).
- 적용: 049에 연결했으며 공통 전이는 다른 개체도 조합 가능하다. 999/173/좀비의 이동 정책은 변경하지 않았다.

## 문제와 제약

기존 화면 순환 생성은 049가 없는 화면에 미처리 아이콘을 쌓고, 바닥별 물리는 모니터 경계를 넘지 못한다. 기존 상한/수명·드래그 우선·봉쇄 계약을 유지하면서 생성 위치와 명시적 모니터 이동을 함께 바꾼다.

## 결정

- Main이 활성 소비자의 위치를 SpawnAnchor 값으로 공급하고 ObjectSpawnPolicy가 화면을 선택한다. 공용 월드는 Doctor/컨트롤러를 참조하지 않는다. 초기 생성도 위치 공급자 연결 이후 실행한다.
- ScreenLocator는 물리 픽셀의 몸/화면 중첩 면적을 사용하고 동률/빈 공간에서는 이전 유효 화면을 유지한다. 없는 앵커는 생성하지 않고, 드래그/전이는 생성 회차를 보류한다.
- MonitorRoutePlanner는 현재 위치→출발 바닥, 도착 바닥→목표의 실제 발판 경로를 모두 검사한다. 기존 PlatformNavigator에 위치/지지면을 명시한 RouteFrom을 추가해 경로 탐색과 캐시를 재사용한다.
- 공통 PortalTransferState는 출발/비표시/도착 시간, 단일 위치 확정, 완료 한 번을 보장한다. DoctorBehavior는 목표·예약·로컬 우선·원격 대기·취소를 소유한다. 물리 경계 제한을 없애지 않는다.
- 전이 중 물리는 정지하지만 행동 시계는 진행한다. 봉쇄는 행동 시계까지 멈춘다. 포털 표현의 비표시를 개체 OFF로 사용하지 않는다.
- PortalFrame 읽기 모델을 PortalPresentation이 소비한다. 출발/도착 효과는 별도160px 창이며 기존 ActorWindowLifetime/OverlayStackCoordinator로 정리한다. 본체 아트의 픽셀은 유지하고 렌더 투명도/크기만 바꾼다.
- 일반 이동의 거리 기반 시간 예산은 선택 옵션으로 049에만 적용한다. 2×예상 거리/유효 속도+4초, 최소 기존12초·구간 최대180초, 전체 목표 시도360초이며 기존 정체1.5초와 구분한다. 복잡한 발판 경로는 플랫폼 폭 합계를 거리의 보수적 여유로 포함한다.

## 대안과 선택 이유

모든 모니터를 하나의 바닥으로 합치면 단차·빈 공간·작업 영역 경계를 새 물리 규칙으로 풀어야 한다. 좌표만 즉시 바꾸면 입력/예약/봉쇄와 연출 완료의 순서가 분산된다. 명시적 전이 상태를 선택하고 같은 화면 내 실패 우회는 허용하지 않는다.

## 영향과 검증

모의44개·실제 두 화면 포털/입력103개, 기존 회귀, 최종 EXE 사용자 확인은 PLAN 증거에 연결한다. 실제 두 화면은96dpi·음수 원점·높이 차이가 있는 배치다. 혼합 DPI/세 화면/물리 모니터 분리의 일부는 모의 검사다. 창 내부 RGBA 캡처가 보조 모니터에서 검게 읽히는 환경 제약은 소유 수신기 위 실제 화면 캡처로 구분했다.
