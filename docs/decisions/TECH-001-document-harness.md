# TECH-001 문서 역할 분리와 Node 기반 구조 검사

- 결정일: 2026-11-23
- 결정 주체·근거: 사용자가 제안된 문서 구조와 PLAN-001 구현을 요청함.
- 관련 작업: [PLAN-001](../plans/PLAN-001-agent-harness.md).
- 기준 기획: [기획 원본](../../SCP_site-desktop.md).
- 적용 위치: [루트 MAP](../../AGENTS.md), [작업 지침](../agents/workflow.md), [문서 검사기](../../scripts/validate-agent-docs.mjs).
- 적용 여부: 문서·검사기 범위에 적용. 게임 실행 하네스는 후속 PLAN에서 구현.
- 대체 관계: 최초 결정.

## 문제와 제약

프로젝트에는 기획 원본만 있어 작업 재개·현재 범위·완료 증거를 관리할 기준이 필요하다.
루트는 MAP만 맡고 세부 지침·계획·결정은 각각 지정된 위치에서 관리해야 한다.

## 결정

- 루트는 탐색 링크만 담고 작업 절차와 PLAN 관리 규칙을 docs/agents에 둔다.
- 기획 원본을 보존하고 docs/game-design에서 안내한다. 제품 규칙을 중복 복제하지 않는다.
- PLAN 메타데이터를 진행 상태의 원본으로 하고 목록과 대조한다. active 최대 1개, 0개는 정상이다.
- 후속 작업은 proposed로 두고 문서 작성과 제품 구현 완료를 구분한다.
- 검사기는 Node.js 표준 라이브러리로 구현하고 별도 설치 패키지를 요구하지 않는다.
- 검사기 오류 탐지는 임시 문서 fixture를 사용하는 node:test로 검증한다.

## 대안과 선택 이유

- 모든 규칙을 AGENTS.md에 모으기: 사용자의 MAP 원칙과 맞지 않고 필요한 지침 탐색이 어려워 제외.
- Doom_Inc 문서 전체 복사: Unity·Android·특정 자산·승인 정책이 섞이므로 역할과 원칙만 이식.
- Markdown/YAML 외부 라이브러리 도입: 현재 단순 메타데이터와 로컬 파일 링크 검사에는 불필요하여 보류.

## 영향과 검증

- 문서 형식은 단순 front matter와 인라인 Markdown 링크를 사용한다.
- 검사 범위는 필수 문서·줄 수·PLAN/TECH 메타데이터와 ID·목록 일치·active 수·로컬 파일 링크다.
- 코드 블록 안의 예시는 링크로 해석하지 않는다. 웹 주소·제목 앵커·참조형 링크는 검사하지 않는다.
- 승인 근거의 진위·완료 증거의 의미·제품 동작은 자동 판정하지 않는다.
- 게임 엔진 설치·프로젝트 구조·런타임 인터페이스 선택은 이 결정의 범위 밖이다.
- 실제 검증 결과는 PLAN-001에서 확인한다.
