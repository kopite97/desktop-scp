# PLAN-017 공통 FSM·이동 기반과 SCP 책임 분리

작성·실행·상태 전환은 [PLAN 관리 지침](plan.md)을 따른다.

## 목표와 범위

- 목표: 기존 SCP-999·049·173과 좀비가 공통 FSM 실행 규약·환경 관찰·이동 기반을 재사용하고, SCP별 행동·물리·조작·표현의 변경이 서로 불필요하게 전파되지 않도록 한다.
- 관찰 가능한 개선: 049가 화면 끝이나 도달 불가능한 목표에서 무기한 보행하지 않고 복구한다. 999는 커서가 멀어도 유효한 공간에서 대기와 배회를 반복한다. 기존 치료·관찰·입력·활성화·트레이 계약은 유지한다.
- 요청 근거: 2026-11-25 사용자 공통 Idle/Moving·SCP별 특수 행동·스크립트 추상화와 디커플링 검토에 이어 “프로젝트 코드 구조 개선을 위한 PLAN을 방금 검토한 사항을 기반으로 작성해줘.”
- 포함: 현재 개체들의 책임 분리, 공통 FSM과 이동 결과 계약, 제한된 발판 경로 탐색·정체 복구, 환경 스냅샷, 공용 월드와 좀비 분리, 등록·수명 연결, 진단 이전, 회귀·짧은 비용 비교·로컬 EXE 검증.
- 제외: 새 SCP·새 아트·조명 제작, 임의 차원의 범용 길찾기 엔진, 모든 클래스의 인터페이스화, 대형 공통 상속 계층, ECS/DI 프레임워크, 동적 플러그인, 멀티스레드 AI, 저장 형식 변경, 설치·서명·외부 배포·Git push, 장시간·고부하 측정.
- 기존 승인 아트·효과는 재사용한다. 본 PLAN의 경계/정체 복구와 배회 보완 외에 173 공격 조건·치료 시간·수명·스트레스·강한 연출 등의 밸런스는 변경하지 않는다.

## 조사한 문제와 수정 대상

- `PlatformWorld`는 바닥 끝에서 좌표를 제한해도 요청 수평 속도를 남기고, `DoctorAnimation`은 그 속도로 보행을 선택한다. 위치와 보행 표현이 어긋나는 경로가 있다.
- `PlagueState`는 가까운 대상 선택·이동·치료·드래그·표현 갱신을 함께 다룬다. 시간 초과 후 같은 도달 곤란 대상을 다시 선택할 수 있다.
- `Scp999State`는 커서 거리 조건으로 이동하며 자율 배회 목표가 없다. 애니메이션 태그·재생 시간이 행동 판정에 직접 결합되어 있다.
- 여러 컨트롤러가 Windows 창·화면·입력을 개별 관찰한다. `SystemController`의 화면 참조도 999에 의존한다.
- `DesktopObjectState`에는 `PlagueSettings`·좀비 행동·애니메이션이 남아 있고 공용 표시는 `PlagueState`를 참조한다.
- 049의 진단 호환 Tick/Publish는 공용 월드 위임을 포함한다. 제품과 하네스의 갱신 경로를 함께 이전하지 않으면 중복 갱신을 유발할 수 있다.
- 위 내용은 코드 조사 결과이며 사용자가 관찰한 당시의 실행 추적을 수집한 것은 아니다. 구현 전 재현 사례를 고정한다.

## 설계 계약

### 공통 FSM과 개체별 조합

- 공통화 대상은 상태 진입·갱신·종료·전환·취소·전환 이유 기록이다. 각 개체가 자신의 FSM 인스턴스·현재 상태·목표·타이머를 소유한다. 가변 상태 객체를 여러 개체가 공유하지 않는다.
- `Idle`은 정지와 대기, `Moving`은 이동 요청과 결과 처리를 담당한다. 대기 시간·목적지 선택·도착 후 행동은 SCP별 정책/설정으로 전달한다. 공통 상태 안에서 SCP ID로 분기하지 않는다.
- SCP별 특수 상태도 같은 실행 규약을 따른다. 049는 탐색/치료, 999는 배회/추적 목표 선택과 상호작용, 173은 관찰/관찰 해제 대기/공격을 구성한다. 좀비는 기존 배회 규칙에 공통 이동을 적용한다.
- 173에는 보행 상태를 강제하지 않는다. 공통 FSM·시간·취소 계약을 사용하면서 순간이동·공격 규칙을 유지한다.
- 전환은 지정된 갱신 경계에서 적용하고 한 갱신의 연쇄 전환을 제한한다. Enter/Exit는 전환당 한 번 호출하며 이벤트 콜백의 재진입·오래된 요청을 방지한다.
- 목표 예약은 상태 사이의 공유 행동 문맥이 소유한다. Moving → Treating에서는 예약을 넘겨 유지하고 실패·취소·OFF에서는 해제한다. 모든 Exit에서 무조건 해제하는 방식은 사용하지 않는다.

### 책임과 갱신 소유권

| 책임 | 소유·입출력 계약 |
| --- | --- |
| 활성화 관리자 | Enabled/Active와 전환 이유. 전체 봉쇄 원본은 SystemOptions 유지 |
| 환경 공급자 | 시각·버전이 있는 읽기 전용 화면/창/포인터/버튼/활동 입력. 실제·모의 공급자 교체 경계 |
| 런타임 갱신 조정 | 환경 전달 → 조작/중단 우선 판정 → 행동/이동 명령 → 물리 → 결과/사건 → 표현 순서를 조정 |
| 개체 행동 FSM | 의도·목표·행동 시간·특수 규칙. 직접 Win32/Node/텍스처 조작 금지 |
| 이동 처리 | 경유지·도착/막힘/불가/취소 결과·재계산. 발판과 충돌은 기존 PlatformWorld에 위임 |
| 물리 | 실제 위치·속도·지지 발판·점프·낙하·균형. 행동 FSM이 별도 위치 원본을 유지하지 않음 |
| 상호작용 | 드래그/쓰다듬기 명령과 자율 행동 제어권. FSM·물리에서 동시에 이동시키지 않음 |
| 공용 월드 | 오브젝트 ID·존재·예약·원자적 명령·수명. 특수 행동의 판단과 표현은 분리 |
| 표현 | 행동/물리 읽기 모델과 사건을 받아 애니메이션·효과·창을 갱신. 표시 여부로 논리 상태를 역산하지 않음 |

- 각 시계·물리·월드·표현의 갱신 소유자는 하나다. 조정자는 순서만 담당하며 SCP별 규칙·OS 호출까지 흡수하지 않는다. 각 컨트롤러의 중복 자동 Tick/Publish 경로를 제거한다.
- 행동·물리·상호작용은 독립 축으로 유지한다. MovingAndFalling 같은 조합 상태를 늘리지 않는다. 낙하 중 이동 목표 유지/재검사는 행동 정책으로 정의한다.
- 애니메이션은 행동과 실제 운동 결과를 따른다. 행동이 재생 완료를 기다려야 할 경우 명시적 완료 신호/행동 잠금을 사용하고 특수 리소스 태그 비교를 행동 코드에서 제거한다.
- 공통 창 수명·좌표·입력 영역·스택 등록/해제는 실제 중복이 있는 부분만 조합 객체로 추출한다. SCP별 외형·히트 마스크·효과는 개별 표현기가 유지한다.

### 환경 관찰과 이동

- 화면/창 관찰을 공통 공급자로 모으고 기존 0.5초 화면 비교·50ms 창 관찰 계약을 출발점으로 사용한다. 포인터는 갱신 단위로 공유하고 입력 이벤트는 누락·중복 전달하지 않는다.
- 창 identity·가림·최소화·종료·화면 선택·배율·물리 픽셀 계약을 보존한다. 수집 시각·실패/오래됨·복귀 시 재수집을 표현한다. 커서 취득 실패 시 과거 좌표를 새 입력으로 취급하지 않는다.
- 배치 버전은 실제 의미 있는 환경 변경 때만 증가한다. 관찰마다 증가하는 기존 Revision을 경로 캐시 무효화 기준으로 그대로 사용하지 않는다.
- 원본 창 관찰은 공유하되 몸 크기·점프 능력별 발판/경로는 분리한다. 캐시가 필요하면 환경 버전과 개체의 이동 조건을 키에 포함한다.
- 기존 발판 모델의 보행·점프·하강 연결 범위 안에서 도달 가능성을 판정한다. 동일 화면이라는 이유만으로 목표를 도달 가능으로 처리하지 않는다. 보장할 수 없는 연결은 실패/대기 결과로 반환한다.
- 이동 결과는 요청 방향, 실제 자기 보행 변위, 발판 운반 변위, 실제 속도, 경유지 진행, 도착/막힘/불가/취소 이유를 구분한다. 화면 끝에서 정지하면 보행 애니메이션과 점액 생성도 실제 운동 결과를 따른다.
- 정체 감지는 점프 준비·낙하·사용자 조작·봉쇄를 구분하고 경로 진행을 관찰한다. 재계산/재시도 상한과 대기 시간을 두어 동일 실패 목표의 무한 재선택을 방지한다.
- 실패 기억은 목표 삭제·의미 있는 환경 변경·개체 재활성화 시 필요한 범위에서 무효화한다. 시간 제한을 늘리는 것만으로 복구를 구현하지 않는다.

### 수명·월드·등록의 디커플링

- 개별 OFF는 행동 취소·예약/일시 효과 정리, 전체 봉쇄는 기존 보존 계약에 따른 일시 정지다. Idle 전환으로 봉쇄를 대체하지 않는다. 중단 시간은 재개 시 따라잡지 않는다.
- 드래그는 자율 행동보다 우선한다. 해제·재활성화·봉쇄 해제 때 최신 환경과 목표를 검사한다. 봉쇄 중 OFF를 선택하면 보존보다 취소를 적용한다.
- 049 소유 좀비의 개체·시간 보존, 일반 복제 대상의 소비자 기반 활동, 비활성 스트레스 제외, 강한 연출 실행 직전 재검사, 트레이 시작/숨김/종료 계약을 유지한다.
- 공용 월드는 중립적인 오브젝트 설정을 사용한다. 치료 설정과 좀비 설정/행동을 분리하되, 변이·파손의 최종 예약/소유자 검사는 월드 명령 경계에 남긴다.
- 공용 표시가 Doctor를 직접 받지 않도록 치료 진행/대상/효과 사건의 좁은 데이터 계약으로 바꾼다. 삭제 후 잔상의 비상호작용·텍스처 유지/해제 계약을 보존한다.
- ScpCatalog에는 필요한 서비스와 생성 문맥을 전달한다. Main은 조립 지점으로 남고 SCP별 필드 변경에 의존하는 등록 코드를 줄인다. 기능별로 계속 늘어나는 bool 대신 실제 필요한 의존성을 명시한다.
- SystemController의 모니터 정보는 공통 환경에서 얻는다. 기존 StressState·아이콘 캐시·OverlayStackCoordinator·WindowsDesktop은 재사용한다.
- 모든 클래스에 인터페이스를 추가하지 않는다. 교체가 필요한 환경·시간/난수·외부 효과 경계와 행동 실행 규약부터 작게 분리한다. 난수는 시드 재현이 가능해야 한다.

## 제품 동작 보완안과 수치 관리

본 절은 2026-11-25 PLAN 실행 승인으로 구현 범위에 채택했다. 기존 확정 수치는 별도 근거 없이 바꾸지 않는다.

- 049: 도달 가능한 치료 대상 우선 선택, 경로 실패 시 예약 해제와 제한된 재시도, 대안이 없으면 대기. 유효한 이동 경로·대상이 생기면 탐색을 재개한다. 구조 개선을 위해 순간이동을 추가하지 않는다.
- 999: 커서 관심이 없으면 유효한 목적지로 배회하고 도착 후 대기한다. 가까운 커서에는 도달 가능한 발판 위치를 목표로 삼는다. 추적 시작/해제 조건을 다르게 두어 경계 진동을 방지한다. 도달할 수 없는 커서를 무기한 추적하지 않는다.
- 999의 쓰다듬기·드래그·타이핑 반응·낙하/착지와 기존 효과를 보존한다. 배회 가능한 공간이 없으면 정지가 정상 결과이며 이를 정체 실패로 반복 처리하지 않는다.
- 173과 좀비는 기존 특수 행동을 유지하며 구조를 이전한다. 새로운 공격/군집 행동은 범위 밖이다.
- 신규 대기 범위·배회 거리·추적 해제 거리·정체 관찰 시간·재시도 상한은 전용 설정으로 분리한다. 단계 A에서 기존 수치와 구별한 제안값·선정 이유·검증 상한을 기록하고 단계 D에서 실제 관찰에 따라 조정한다.

- 신규 수치: 999 대기 1~3초·배회 80~220px·추적 해제 520px(시작 420px 유지), 일반 정체 1.5초, 이동 제한 12초, 좀비 장거리 코너 이동 60초, 049 탐색 0.2초·실패 최대3회·기존 재시도 간격의 배수 대기. 몸 크기/속도와 기존 도약 물리는 유지한다.
- 공통 BehaviorContext는 현재 필요하지 않아 별도 파일을 만들지 않고 개체 행동 문맥에서 목표/예약을 소유한다. IDesktopEnvironmentSource는 스냅샷 파일, ZombieSettings는 중립 월드 설정 파일에 함께 선언한다.
- 신규 CompanionAnimation은 태그/재생 시간/완료 신호를 분리한다. 진단 전용 PlagueScenario는 제품 월드/의사 명령을 순서대로 호출하며 별도 게임 규칙을 갖지 않는다.
- 변경 전 실제 실행 3회 측정(run-002)은 실시간 외부 환경/커서에 노출된 관찰값이다. 고정 입력 성능 보장으로 사용하지 않으며 관찰 공유의 호출 수는 별도 재현 검사로 확인한다.
- 캐시는 각 개체의 PlatformNavigator에 둔다. 의미 있는 물리 Revision과 시작/목표 발판 쌍을 키로 성공/실패를 재사용하며 최대128개로 제한한다. 같은 발판 내 목표 이동은 재탐색하지 않는다.
- 최종 책임: ScpRuntime이 월드→999→049→173 순서를 조정하고 모의 환경도 같은 Advance 경로에 전달한다. 표현의 즉시 알파 입력 갱신은 OS 경계에서 커서를 읽을 수 있지만 AI의 환경 판단은 공유 스냅샷을 사용한다. 환경 실패는 null 포인터/마지막 수집 시각으로 다루며 별도 복잡한 오류 상태 체계는 도입하지 않았다.
- 기준선 CPU 입력을 완전히 고정하지 못했다. 사전 보장하지 않은 CPU 개선율 대신 실제3회 관찰값과 고정 모의 입력의 수집/갱신 계수·경로 캐시 검사를 분리했다. 총 CPU 감소는 입증되지 않았으며 반복되는 일방적 증가도 확인되지 않았다.
- 내보내기는 최초1회 이후 최종 경로 캐시와 공유 갱신 회귀 보완이 있어 1회 추가했다(run-044→053). 로컬 격리 대상과 외부 배포 제외는 유지했다.
- 시작 검사의 부트 포커스 실패는 숨기지 않는다(run-054/055). 전체 제어창은 노출되지 않았고 사용자 메뉴·OFF 복원은 통과했으므로 본 구조 개선의 기능 기준은 충족한 것으로 판정한다. 부트 창의 포커스 획득 자체는 남은 제한이며 시작 시 무포커스까지 완벽히 검증했다고 보고하지 않는다.
- run-001은 첫 애니메이션 갱신이 착지 프레임을 선택하는 진단 초기화 문제로 실패했다. 반복 프레임 갱신을 적용한 run-002에서 보고된 세 동작을 재현했다. 실패 증거는 보존한다.
