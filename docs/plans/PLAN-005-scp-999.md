# PLAN-005 SCP-999와 공통 스트레스 상태

## 목표와 범위

- 목표·포함: SCP-999 커서 추적·타이핑 반응·쓰다듬기, 공통 스트레스 상태와 반경 내 감소, 상태별 표현 연결.
- 기획의 하트/음표·이동 점액 자국에 대한 생성·수명·정리·클릭 투과를 포함한다. 정식 아트 미수령 시 임시 표현으로 동작을 검증한다.
- 정식 아트가 실행 중 전달되면 이 범위의 임시 표현을 교체하고 적용 리비전·제품 화면 검증을 기록한다.
- 우선 실행 단계 A: r002 4장 조명 방향/반사/반투명/좌우 반전 시험 → idle/move 12프레임 제작·실제 시간 재생 검증. 다른 동작 확장은 이 두 관문 확인 뒤 진행한다.
- 제외: 173/049의 개별 AI·정식 원본 제작(ART 담당)·성장/해금·정식 스트레스 UI·PLAN-008의 과부하 모습·실제 로컬 시간/태양 시스템.
- 요청 근거: 2026-11-23 사용자가 PLAN-005 활성화 및 4장 검증→idle/move 전체 검증 순서로 진행을 명시했다. 이번 실행 우선순위는 단계 A다.
- 추가 요청: 2026-11-23 사용자가 PLAN-005용 ART 계획 생성·상세 요구사항·이 PLAN 갱신을 요청했다. 개발/제작 실행 승인은 아니다.

### 개발에 필요한 재생·합성 계약

| 입력/상태 | 표시 요구 | 개발 책임 |
| --- | --- | --- |
| 추적 대기/이동 | idle/move 및 방향 전환 | 커서 거리·이동 속도와 상태 연결, 본체 위치와 그림 변형 분리 |
| 타이핑 활동 | typing_react와 하트/음표 | 키 내용 수집 없이 활동 이벤트만 사용, 연속 입력 병합·쿨다운·효과 상한 |
| 클릭/문지름 | pet의 반복·회복, 주변 스트레스 감소 | 드래그 이동과 구분, 반경/중복 입력 판정은 공통 상태에서 처리 |
| 도약/낙하/착지 | takeoff/fall/land | PLAN-004 물리 이벤트 연결, 타이핑 튀기와 물리 이동의 이중 적용 방지 |
| 발판 이동/관성 | balance | 실제 지지 상태와 그림 기울임 구분, 안정 시 idle/move 복귀 |
| 지지면 위 이동 | 점액 생성·유지·증발 | 공중 생성 여부·발판 이동/소멸 시 부착/정리 정책·수명·최대 개수 확정 |

- 위 태그는 계약안이다. 구현 시 실제 상태→제출 태그·프레임 매핑을 명시하고 프레임별 ms·일회/반복·종료 자세를 존중한다.
- 시트는 고정 셀로 수령하며 트리밍/회전/중복 병합을 전제하지 않는다. JSON 인덱스·프레임 사각형·태그·시간을 읽고 Aseprite 편집 인덱스와 혼동하지 않는다.
- 전용 importer는 현재 없다. 실제 제출 형식에 맞는 최소 연결 방식을 선택하고 일반 importer 구축을 선행 작업으로 확대하지 않는다.
- 하트/음표·점액·그림자는 본체 클릭 윤곽에 포함하지 않는다. 반투명 몸체의 입력 영역은 알파 임계값과 실제 형태를 고려해 별도 검증한다.
- 최대 변형과 떠오르는 효과가 PLAN-003의 128×128 임시 창 경계에서 잘리지 않도록 표시 영역을 검토한다. 창 확대가 빈 공간 입력 차단으로 이어지면 안 된다.
- 피벗·본체 접점·효과 연결점은 원본 픽셀→표시 배율→기존 물리 화면 좌표 경계로 일관되게 변환한다.
- 진단 조명은 단계 A에 구현했다. [Art 조명 지침](../../Art/docs/agents/lighting.md)에 따라 기본색/보조 맵·대표 샘플·실제 엔진 증거를 연결한다. 제품 전역 조명/시간대 구현은 별도다.
- Scp999 r001은 고정 명암 시안이다. [r002](../../Art/assets/characters/Scp999/revisions/r002/README.md)는 기본색·노멀·반사 맵 4프레임 샘플이며 전체 애니메이션을 대체하지 않는다.
- 엔진 조명 시험은 이 PLAN의 단계 A로 통합했다. [PLAN-009](PLAN-009-scp-999-lighting-sample.md)는 중복 실행 후보를 rejected로 보존하며 기존 시험 설계를 참조한다.

### 단계 A 조명 검증 순서와 판정

1. r002 4장에 CanvasTexture+주광원 하나+주변 밝기를 연결한다. 실제 Compatibility 렌더러에서 좌/우/위, 낮/밤, 기본색/노멀만/노멀+반사, 정상/좌우 반전을 비교한다.
2. 기본색 alpha 보존·세 배경·1배/2배 가독성, 빛 방향과 반사 이동, 반전의 법선 방향을 확인한다. 실패 시 샘플 또는 엔진 연결부터 수정한다.
3. 4장 품질 관문 통과 후 ART-001에서 r003 idle 6장+move 6장 맵을 제작한다. 기존 시간 1040ms/740ms와 바닥 접점을 유지한다.
4. 실제 프레임별 ms로 양 태그를 반복 재생한다. 고정 광원 아래 프레임 경계/루프 경계에서 표면 명암·반사 중심·밝기 변화와 시각적 떨림을 확인한다. 형태 변화에 따른 정상 변화를 구분해 기록한다.
5. 두 창의 공유 조명·숨김/복원·입력 투과·동일 조건 비용을 확인한다. 누락은 미측정으로 남기고 전체 확장 합격으로 처리하지 않는다.
6. 다른 동작 전체 확장은 위 결과 확인 후 진행한다. 두 관문을 통과했으므로 사용자가 지정한 순서대로 r004 전체 50프레임을 제작하고 진단한다. 최종 사용자 시각 승인은 별도다.

- 노멀은 수치 RGB X+/Y+/Z+다. 반사 맵 RGB와 재질 파라미터의 실제 반응을 확인한다. 채택 시험값 shininess .45/specular_color .35와 반사 색 0을 비교했다. Sprite2D.FlipH의 기본 법선 처리를 확인했으므로 수동 채널 반전을 추가하지 않는다.
- 품질 검사는 실시간 Godot 렌더 결과를 사용한다. Aseprite 합성이나 CPU 재현 그림을 엔진 시험으로 보고하지 않는다.
- 비용 예산(진단용 1~2개체): 60Hz 목표, 렌더 CPU/GPU 추가 p95 각각 1ms 이하, 프로세스 CPU 증가 1코어 기준 5%p 이하, working set 증가 32MiB 이하. 측정 횟수·시간·VSync·관찰 부하를 기록한다. 제품 전체 성능 보증은 아니다.
- 최종 비용 비교는 실제 idle/move 재생·1개/2개 표시 창·같은 128×128 공유 렌더 텍스처에서 base/lit를 번갈아 3회, 각 준비 2초+측정 10초로 수행한다. 모든 회차를 기록하고 대응 회차 차이로 비교한다. 초기 5초 정지 측정의 편차/메모리 증가 원인은 별도로 남긴다.

### 단계 A 추가: 외곽선과 반응 효과 조명 제외

- 2026-11-24 사용자 요청으로 ART-002에서 Scp999 r005 외곽선 분리와 Scp999Reaction r001 Unshaded 전달 계약을 추가한다. ART-001 완료 기록·r004 승인은 보존한다.
- 엔진은 중립 부모 아래 lit 몸체/표정 + unlit 외곽선, unlit 하트/음표를 구성한다. 부모 modulate의 의도치 않은 주야간 변조와 원본 알파 이중 적용을 방지한다.
- 4장 관문 후 50프레임을 검증한다. 광원 방향/세기·CanvasModulate·주야간·반전·1배/2배, 경계/알파·전체 재생 동기화·효과 소멸을 실제 Compatibility 렌더러에서 확인한다.
- 비용은 기존 r004 합성 조명과 분리 경로를 같은 재생/해상도/창 조건에서 비교한다. 기존 단계 A 예산을 사용하며 시험 방법과 한계를 새 run에 기록한다.
- 결과는 run-011 이후 새 회차에 저장한다. 제품 행동/물리·전체 효과 스폰 시스템 구현과 구분한다.

### 수령과 완료 경계

1. AssetId·제출 리비전·원본/PNG/JSON·태그·규격·기술 검사 결과·사용자 확인 상태를 대조한다.
2. 승인 전 초안을 시험에 쓰면 미승인 임시 표현이라고 기록한다. 정식 적용본은 승인 리비전을 지정한다.
3. 제출 export 중 필요한 파일만 제품 경로로 복사한다. 작업용 source·리뷰를 런타임에서 직접 참조하지 않는다.
4. 에셋별 handoff에 실제 수령·적용 파일·태그 매핑·제품 검증을 기록하고 이 PLAN에서 연결한다.
5. development 완료는 정식 아트 미수령만으로 막지 않는다. 임시 표현으로 필수 기능을 검증하고 남은 정식 적용은 별도 proposed 통합 PLAN으로 기록한다.
6. 본 PLAN 완료 후 아트가 도착하면 이 PLAN을 재활성화하지 않는다. ART 완료·제작 시각 확인·Godot 적용 검증은 각각 판정한다.
