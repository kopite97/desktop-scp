# PLAN-018 모니터 간 포털 이동과 역병의사 중심 아이콘 생성

작성·실행·상태 전환은 [PLAN 관리 지침](plan.md)을 따른다.

## 목표와 범위

- 목표: 복제 아이콘은 가능한 한 SCP-049가 있는 모니터에 생성하고, 사용자 드래그 등으로 기존 목표와 모니터가 갈라졌을 때 049가 명확한 포털 연출을 거쳐 이동하여 처리한다.
- 요청 근거: 2026-11-26 사용자 “모니터 간 포털 이동을 구현하기 위한 PLAN을 작성해줘”, “어지간하면 역병의사가 존재하는 모니터에만 아이콘이 생기도록”, 우클릭으로 049를 다른 모니터로 옮긴 경우 포털 이동 가능성 언급.
- 2026-11-26 사용자 “PLAN을 진행해줘.”로 본 PLAN 구현·검증 실행 승인을 받았다.
- 포함: 049 우선 생성 위치 정책, 공통 모니터 전이 경로/상태/표현, 049 목표 선택과 드래그 후 재탐색, 취소·봉쇄·모니터 변경, 실제 두 화면/입력/로컬 EXE 검증.
- 최초 제품 적용은 049다. 공통 전이 구성요소는 다른 SCP도 조합할 수 있게 설계하되, 999의 모니터 추적 조건·173의 공격 이동·좀비의 모니터 이동은 이번에 추가하지 않는다.
- 제외: 모니터 경계를 직접 걸어서 넘는 물리, 같은 모니터 내 막힘을 우회하는 순간이동, 아이콘 자동 재배치/즉시 일괄 삭제, 생성 상한·수명 밸런스 변경, 새 캐릭터 아트·조명·효과음, 별도 포털 설정 UI, 외부 배포·Git push.
- 기존 PLAN-017의 미커밋 코드·문서·증거를 기반으로 하며 이를 덮어쓰거나 과거 검증을 새 결과로 취급하지 않는다.

## 확인한 현재 원인

- [DesktopObjectState.Spawn](../../GodotProject/Scripts/Simulation/DesktopObjectState.cs)은 `_nextId % Screens.Count`로 화면을 번갈아 고른다. 049 위치를 반영하지 않는다.
- 현재 일반 복제 대상은 전역 최대6개·생성 간격6초·수명90초다. 원격 화면의 미처리 대상도 같은 상한을 차지한다. 이번에는 이 수치를 낮추는 대신 생성 위치를 바꾼다.
- 공용 월드 컨트롤러는 049 생성 전 초기 Spawn을 호출한다. 주기적 생성만 고치면 첫 아이콘은 잘못된 화면에 생길 수 있어 초기 조립 순서도 변경 대상이다.
- PlatformNavigator에는 모니터 바닥 간 연결이 없고 PlatformWorld는 현재 바닥 경계에 몸을 제한한다. DoctorBehavior는 도달 불가 목표를 선택하지 않으므로 효과만 추가해서는 모니터 이동이 시작되지 않는다.
- 기존 이동 제한12초는 먼 출발 지점까지 걷는 정상 경로도 중단시킬 수 있다. 경로 구간별 시간 예산과 진전 없는 정체 판정을 분리해야 한다.

## 제품 동작 제안

이 절은 실행 승인으로 채택한 구현 범위다. 아래 수치로 검증했으며 제품 밸런스의 영구 고정값을 뜻하지 않는다.

### 아이콘 생성 위치

| 상황 | 제안 동작 |
| --- | --- |
| 049가 활성 상태이며 위치가 유효함 | 자동 생성과 제어창 Spawn icon clone은 049가 있는 모니터만 후보로 사용 |
| 같은 모니터에서 안전한 생성 공간이 없음 | 해당 생성 회차를 건너뜀. 다른 모니터로 임의 분산하지 않음 |
| 049를 우클릭으로 드래그 중 | 새 생성 일시 보류. 드롭 후 위치를 다시 판정하며 보류된 생성을 몰아서 실행하지 않음 |
| 049가 포털 전이 중 | 새 생성 보류. 도착/취소 확정 후 그 위치를 기준으로 재개 |
| 049 OFF, 173 ON | 공용 대상 소비자 계약을 유지하기 위해 173의 유효한 모니터를 대체 위치로 사용 |
| 대상 소비자 모두 OFF 또는 봉쇄 중 | 새 생성 없음. 기존 월드 일시 정지 계약 유지 |
| 유효한 모니터를 판정할 수 없음 | 새 생성을 보류하고 최신 환경에서 재평가 |

- 모니터는 현재 유효한 환경의 화면 경계와 몸 위치로 판정한다. 화면 사이 빈 공간·경계에서는 중첩 면적과 이전 유효 화면으로 안정적으로 결정하며, 변화 중인 드래그 좌표를 생성 기준으로 사용하지 않는다.
- 생성 위치는 해당 작업 영역 안에 몸 전체가 들어가는 바닥 후보로 제한한다. 선택 모니터 옵션이 있으면 허용 화면 집합 밖에 생성하지 않는다.
- 전역 최대6개·간격6초·수명90초, 좀비의 별도 상한/수명, 실제 아이콘 취득 실패 시 생성 건너뜀은 유지한다. 모니터별로 최대치를 복제하지 않는다.
- 049가 떠난 화면의 기존 아이콘은 이동·삭제·수명 초기화하지 않는다. 치료/회수/파손 또는 기존 자연 만료로 정리한다. 새 위치의 화면이 비어 있어도 전역 상한을 넘겨 생성하지 않는다.
- 진단의 명시적 SpawnAt은 양쪽 화면에 대상을 준비할 수 있게 유지한다. 일반 UI/자동 Spawn은 같은 생성 정책을 사용한다.

### 049의 목표 선택과 사용자 이동

- 현재 모니터의 도달 가능한 대상을 먼저 선택한다. 없을 때만 다른 모니터의 포털 경로가 유효한 대상을 검토한다.
- 우클릭 드래그 시작 시 기존 목표·예약·이동 요청을 취소한다. 드래그 자체를 포털 이동으로 바꾸거나 커서에서 몸을 빼앗지 않는다.
- 다른 모니터에 드롭한 뒤 착지를 기다리고, 원격 목표 선택만 5초 유예하는 방안을 적용한다. 로컬 목표 처리는 가능하다. 재드래그 시 유예를 다시 시작한다.
- 유예 후 로컬 목표가 없고 이전 화면 등에 미처리 대상이 있으면 포털을 사용해 돌아갈 수 있다. 사용자 이동 직후 즉시 되돌아오는 동작은 금지한다.
- 목표를 선택한 이동 중에는 새 로컬 아이콘 생성만으로 경로를 바꾸지 않는다. 목표 삭제/드래그/파손, OFF, 환경 무효화 등 명시적 사유에서만 재평가한다.
- 원격 목표는 출발 지점까지의 경로와 도착 지점에서 목표까지의 경로가 모두 유효해야 예약한다. 목표 발판 자체가 도달 불가이면 포털로 직접 그 발판에 올려놓지 않는다.
- 전이 완료 후 원격 재이동에는 초기5초 재사용 대기를 둔다. 로컬 보행/치료에는 적용하지 않는다. 안정된 실패 기억과 함께 반복 왕복을 제한한다.

### 포털 경로와 연출

1. 도달 가능한 출발 지점을 정해 걸어간다. 지점은 현재 화면의 바닥 안쪽이며, 경계에서 제자리 걷게 하는 목표를 만들지 않는다.
2. 본체 근처에 타원형 포털이 열리고 본체가 축소/소멸한다.
3. 본체가 완전히 보이지 않는 시점에 위치를 정확히 한 번 변경한다.
4. 목적 화면의 안전한 바닥 지점에서 같은 포털로 본체가 나타난다.
5. 입력/물리 제어를 정상 상태로 돌리고 목표까지 걸어가 치료한다.

- 총 연출 초기값1.0초(출발0.4초·비표시 이동0.2초·도착0.4초). 이전 검토 범위0.8~1.2초 안에서 실제 화면 확인 후 조정한다.
- 출발/도착 포털은 각 화면 안의 독립 효과 창으로 표현한다. 모니터 사이 빈 공간을 가로지르는 거대한 창을 만들지 않는다.
- 목적 화면이 왼쪽/오른쪽/위/아래인지에 따라 가까운 바닥 쪽 진입 위치를 고르되, 몸/효과 크기와 작업 표시줄 영역을 제외한 안전 여백을 보장한다. 직접 맞닿지 않은 화면도 전이할 수 있다.
- 안전한 지점과 도착 후 실제 경로가 없으면 Unreachable 또는 Cancelled로 종료한다. 한 모니터만 있으면 전이 기능을 사용하지 않는다.
- 전체 화면 가로줄·깜빡임·섬광·강한 흔들림 없이 작은 포털과 제한된 입자를 사용한다. 출발과 도착의 모양/색을 맞춰 의도된 이동으로 읽히게 한다.
- 기존 승인 본체 아트는 변경하지 않는다. 최초 효과는 코드 기반 도형/재질로 구현하는 개발 범위이며 별도 아트 리비전·조명 연결은 해당 없음이다.

## 책임 분리와 중단 계약

- 상위 모니터 경로 계획은 Walk → Transfer → Walk 구간을 구성하고, 기존 PlatformNavigator는 각 화면 내부 보행/점프/하강을 담당한다. 물리가 임의로 화면 경계를 연결하거나 실패 시 자동 순간이동하지 않는다.
- 공통 PortalTransferState/실행기는 전이 ID·출발/도착 화면·진행 단계·위치 확정 여부만 소유한다. 049 대상 선택과 예약은 DoctorBehavior가 계속 소유한다. 공통 코드에 SCP ID 분기를 넣지 않는다.
- 스폰 정책은 독립된 값 입력(우선/대체 화면·일시 보류·환경 버전)을 받아 후보를 결정한다. Main/등록 문맥이 SCP 위치를 공급하며 DesktopObjectState가 DoctorBehavior/PlagueController를 직접 참조하지 않는다.
- 초기 아이콘 생성은 SCP 등록·위치 정책 연결 이후 실행한다. 첫 프레임 생성, 수동 생성, 주기 생성 모두 같은 정책 경로를 사용한다.
- 포털 표시 데이터와 표현기를 분리한다. 효과 창은 기존 ActorWindowLifetime/OverlayStackCoordinator에서 정리하고 전체 클릭 투과·비활성 포커스를 유지한다.
- 전이 중 본체 숨김은 개별 OFF/봉쇄와 다른 표현 상태다. SetVisible(false)를 행동 정지 대신 호출해 전이 시계를 멈추는 순환 의존성을 만들지 않는다.
- 연출 중 물리와 AI의 중복 위치 변경을 막고 쓰다듬기/드래그 입력을 받지 않는다. 보이지 않는 본체의 입력 영역도 제거한다. 출발 준비 보행 중에는 우클릭 드래그가 우선한다.
- 예약은 보행→전이→보행 동안 유지하며 목표 변경/취소/개별 OFF/종료에서 해제한다. 봉쇄는 전이 시계·물리·예약을 보존하고 모든 본체/효과/입력 영역을 숨긴다.
- 재개 시 목표·화면·도착 지점을 재검사한다. 위치 확정 전 취소는 출발 위치, 확정 후 취소는 도착 위치를 기준으로 정리한다. 해당 화면이 제거됐으면 현재 남은 작업 영역으로 안전하게 복구한다.
- 전이 ID/세대를 검사해 과거 완료 콜백이 OFF·종료 후 몸을 재출현시키거나 위치를 두 번 바꾸지 못하게 한다.
- 장거리 시간 예산은 각 보행 구간의 거리/유효 속도+여유와 포털 고정 시간으로 산정한다. 진전 없는 정체1.5초는 별도로 유지한다. 경로 갱신마다 제한 시간이 무한히 초기화되지 않도록 총 시도 상한을 둔다. 구체 공식/상한은 단계 A에서 화면 크기/속도 fixture로 확정한다.
