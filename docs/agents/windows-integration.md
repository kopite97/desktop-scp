# Windows 연동 지침

적용: 모니터·창·입력 활동·시스템 지표·외부 창 효과.
탐색: [아키텍처](architecture.md), [실행 하네스](harness.md), [검증](verification.md).

## 좌표와 관찰

현재 오버레이는 [TECH-003](../decisions/TECH-003-overlay-islands.md)의 개체별 네이티브 창을 사용한다.
상태·Win32 커서는 물리 픽셀이고 Godot 정규화 원점과의 변환은 WindowsDesktop 한 곳에서 수행한다.
화면 배치는 0.5초 주기로 비교하며 변경 시 드래그 취소·작업 영역 재배치를 수행한다.

- 화면 픽셀·논리 좌표·Godot 좌표의 의미와 변환 책임을 명시한다.
- 음수 모니터 원점·서로 다른 배율·모니터 연결 변경을 검증 시나리오에 포함한다.
- 창 프레임과 실제 보행 가능한 발판의 판정은 구분한다. 가려짐·최소화·최대화·종료 처리 규칙을 정한다.
- OS 관찰 결과를 게임 입력으로 전달하고 게임 규칙 안에 네이티브 호출을 흩어 놓지 않는다.
- 수집 시각·갱신 주기·사라진 창·오래된 관찰값의 처리를 명시한다.
- 기획의 Win32/Godot API 후보는 설치 환경과 공식 문서로 확인한 뒤 사용한다.

## 입력과 가짜 오브젝트

- 빈 영역은 실제 작업 창으로 입력이 통과해야 한다. 개체·UI의 입력 영역은 화면 위치와 함께 갱신한다.
- 입력 판정의 단위·경계·드래그 종료·개체 숨김 시 해제 동작을 검증한다.
- 타이핑 반응에는 입력 발생·시각 등 필요한 활동 정보만 사용한다. 입력 문자열을 수집·저장하지 않는다.
- 가짜 파일·쓰레기·좀비 파일은 게임 내부 오브젝트다. 실제 바탕화면 파일 생성·변경·삭제로 구현하지 않는다.
- 검증 증거에 다른 앱의 문서 내용·키 입력·불필요한 창 제목을 저장하지 않는다.

## 외부 창 연출

- 강한 연출은 제품 기본값 OFF를 유지한다.
- 외부 효과 요청과 실행을 분리하고 OFF·봉쇄 상태에서는 실행하지 않는다.
- 대상 창이 사라지거나 조건이 바뀌면 중단한다. 핸들 값만으로 오래된 대상을 계속 신뢰하지 않는다.
- 시작 위치·효과 수명·취소·복원 책임을 정한다. 사용자 창 이동과 충돌할 때의 동작을 결정하고 기록한다.
- 실제 창 이동 검증은 우선 테스트가 소유한 창을 대상으로 한다.
- 실제 OS 효과 없이 모의 실행 기록으로 확인한 범위와 실제 효과를 관찰한 범위를 구분한다.

## 봉쇄와 종료

- 최소 즉시 숨김·종료 경로를 오버레이 기술 검증 단계에 둔다. 정식 UI·트레이·셔터 연출은 후속 단계에서 구현한다.
- 봉쇄는 표시뿐 아니라 게임 시간·스트레스 진행·예약된 OS 효과의 중단을 함께 다룬다.
- 봉쇄 중 클릭 영역이 남아 작업 창 입력을 가로채지 않는지 확인한다.
- 해제 시 같은 세션 상태로 복귀하고 중단 중 시간이 누적되어 한꺼번에 반영되지 않게 한다.
- 정상 종료·실패·재시작 시 입력 감시·단축키·트레이·네이티브 자원을 정리한다.

## 지표의 의미

- 마스터 볼륨 설정과 실제 출력 레벨을 같은 값으로 취급하지 않는다. 선택한 신호와 단위를 기록한다.
- CPU·RAM 사용량은 대상·수집 간격·평활화·임계값을 명시한다.
- 지표 반응은 모의 입력으로 먼저 검증한다. 이를 위해 실제 시스템 부하를 높일 필요는 없다.
- 제품 수치와 미정 동작은 [기획 MAP](../game-design/README.md)에서 추적한다.
